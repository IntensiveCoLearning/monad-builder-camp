\## Week 1｜Monad 理解｜为什么 Monad 体验不同

\- 我选择的场景是一个链上社区闯关小游戏。玩家通过完成挑战获得积分，积分影响公开排行榜，赛季结束后可以根据排名领取链上 Badge 或奖励。

\- 高频交互：

1\. 玩家提交挑战结果。

2\. 合约更新玩家积分。

3\. 排行榜更新玩家名次。

4\. 玩家完成每日任务。

5\. 玩家领取阶段性奖励。

\- 慢链上的问题：

1\. 如果每次提交结果都要等待很久，玩家无法连续游戏。

2\. 如果手续费较高，频繁更新积分的成本可能超过游戏奖励本身。

3\. 如果多人同时参与时网络拥堵，排行榜会延迟更新，玩家无法获得实时反馈。

\- Monad特点对应到产品问题：

| 产品问题 | Monad 可能提供的帮助 |

| ---------- | ----------------------- |

| 多人同时提交交易 | 高吞吐量 |

| 玩家等待结果 | 较短出块和确认时间 |

| 频繁操作成本过高 | 更大的网络容量使高频应用更可行 |

| 需要重新开发整套合约 | EVM 兼容，可复用 Solidity 和工具 |

| 排行榜需要快速读取 | 可配合 RPC、Indexer 和前端实时更新 |

\- “是否需要上链”的判断：

游戏动画、聊天和临时匹配不需要上链，可以使用普通数据库；最终积分、公开排名、奖励领取和数字道具归属适合上链，因为这些数据涉及公平性、可验证性和玩家资产所有权。

\- 经验总结

\===================

任务目的

\----

走通一次完整的智能合约链路：

Solidity 源码

→ 编译

→ 钱包签名

→ 部署到 Monad Testnet

→ 获得合约地址

→ 调用 Read / Write Function

→ 用区块浏览器验证

我完成了什么

\------

部署了一个 `CheckIn` 打卡合约，并完成：

\* 编译合约

\* 部署到 Monad Testnet

\* 调用 Read Function

\* 调用 `checkIn()` Write Function

\* 保存合约地址、部署 Hash、交互 Hash

\* 用区块浏览器确认交易成功

关键理解

\----

\* 部署合约本质上也是一笔交易。

\* 合约地址表示“程序部署在哪里”。

\* Transaction Hash 表示“哪一笔交易完成了这次操作”。

\* Read Function 只读状态，不需要签名，通常没有 Hash。

\* Write Function 会修改状态，需要签名、Gas，并产生 Hash。

\* 前端或 Remix 通常通过“合约地址 + ABI”与合约交互。

\* 钱包的核心作用不是“存币”，而是保管密钥并签名交易。

最重要的经验

\------

1\. 部署前确认网络、Chain ID 和课程专用钱包。

2\. 编译成功后再部署，不要忽略警告和版本问题。

3\. 部署成功后立即保存：

\* 合约地址

\* 部署交易 Hash

\* 交互交易 Hash

\* Explorer 链接

\* 截图

4\. 不要混淆部署 Hash 和函数交互 Hash。

5\. Read Function 没有 Transaction Hash 是正常的。

6\. 测试网没有真实资产价值，但交易、Gas、签名和合约执行逻辑都是真实的。

7\. 不提交私钥、助记词、API Key 或 `.env`。

一句话总结

\-----

这次任务让我真正理解：智能合约不是“写完代码”，而是要经过编译、部署和链上交互，才能成为一个可被钱包和其他应用调用的链上程序。

\# Solidity 留言板合约任务笔记（检索用）

\## 1. 核心概念（黑盒视角）

\- **区块链**：全球共同维护的公共账本，数据不可篡改。

\- **智能合约**：部署在链上的自动执行程序，相当于一个“公开的、永久的类实例”。

\- **Solidity**：写合约的语言，类似 Python 但针对 EVM。

\- **Remix**：浏览器 IDE，用于编写、编译、部署和测试合约。

\- **节点**：运行区块链客户端的电脑，负责验证交易、执行合约。你默认不是节点，通过 RPC 使用网络。

\- **交易**：带数字签名的函数调用请求，包含目标合约、函数、参数、gas 费等。

\- **Gas**：执行合约的计算费用，写操作需要，读操作免费。

\- **矿工/验证者**：打包交易、执行代码、更新状态的角色（以太坊现为 PoS 验证者）。

\## 2. 合约组成（SimpleMessageBoard）

\- **状态变量**`message`（留言内容）`lastSender`（最后留言者地址）`updatedAt`（时间戳）——永久存储在链上。

\- **事件**`MessageUpdated`——通知外界状态变更，可被前端监听。

\- **写函数**`setMessage`——修改状态，需发交易、付 gas。

\- **读函数**`getMessage`——读取状态，免费调用，不需交易。

\## 3. 操作本质

| 操作 | 类型 | Python 类比 | 是否需要 gas |

| ------------ | ------- | ----------------------- | -------- |

| `getMessage` | 读（view） | `SELECT ... FROM table` | 否 |

| `setMessage` | 写 | `UPDATE table SET ...` | 是 |

\### 点击 `getMessage` 时：

\- Remix 构造本地查询请求 → 节点本地执行代码 → 返回当前状态值。

\- 无签名、无交易、无 gas，瞬间返回。

\### 点击 `setMessage` 时：

\- Remix 构造交易（含签名）→ 发送给节点 → 节点验证签名 → 执行代码（改存储、触发事件）→ 返回交易收据。

\- 需要签名、消耗 gas，状态永久改变。

\## 4. 任务步骤（最小闭环）

1\. **编写 Prompt** → 让 AI 生成合约代码（要求：Solidity ^0.8.20、无多余逻辑）。

2\. **在 Remix 新建文件** → 粘贴代码。

3\. **编译** → 选兼容版本 → 点 Compile → 检查无红错。

4\. **人工检查**（至少 3 点）：

\- 函数行为是否符合预期（setMessage 只做三件事）

\- 权限设计（公开留言板无 owner 限制）

\- 有无不必要的复杂逻辑（无数组、payable、外部调用）

\- 安全风险（不涉及资金，无重入）

\- 命名清晰度

5\. **可选修改**：将 `message` 从 `private` 改为 `public`（方便读取）。

6\. **部署到 Remix VM** → 点 Deploy。

7\. **测试**：

\- 先 `getMessage` → 空值。

\- 再 `setMessage("Hello")` → 交易成功。

\- 再 `getMessage` → 看到新值。

8\. **整理提交内容**：Prompt、AI 输出、最终源码、修改说明、检查点列表。

\## 5. 关键检查点（AI 生成代码需人工复核）

1\. **编译是否通过**（版本匹配、语法正确）。

2\. **函数行为**：setMessage 是否只更新留言，无额外转账/循环。

3\. **权限设计**：是否符合预期（公开/私有）。

4\. **安全风险**：有无 payable、外部调用、大数组等危险模式。

5\. **命名清晰**：变量和函数名应自解释。

\## 6. 常见误区

\- `private` 变量 ≠ 链上隐藏，链上数据始终公开。

\- 读函数（view）不消耗 gas，写函数一定消耗。

\- 部署后合约地址固定，代码不可修改（除非用代理模式）。

\- 你的电脑默认不是节点，通过 RPC 服务（如 Infura）接入网络。

\## 7. 下一步扩展方向

\- 部署到真实测试网（Monad Testnet）→ 需要 faucet 领测试币、配置 MetaMask。

\- 添加计数器、权限控制（owner only）、事件过滤等进阶功能。

\## 8. 附：和其他选题的区别和联系

| **合约类型** | **核心功能** | **状态变量数量** | **是否需要数组/映射** | **是否涉及资产** | **权限复杂度** | **典型应用场景** |

| ----------------- | -------------- | -------------- | ----------------- | ------------ | ----------- | --------------------- |

| **留言板**​ | 写一条留言，读当前留言 | 3 | 否 | 否 | 无 | 公开留言墙、测试网 Hello World |

| **投票合约**​ | 创建提案，用户投票，统计结果 | 5~10 | 是（候选名单、投票记录） | 否 | 中（防重复投票） | DAO 投票、社区决策 |

| **打卡合约**​ | 用户每日签到，记录连续天数 | 3~5 | 是（用户→上次打卡时间） | 否 | 低（每人一天一次） | 链上考勤、游戏每日奖励 |

| **NFT Badge**​ | 铸造唯一徽章，转移到用户地址 | 较多（ERC-721 标准） | 是（所有者映射、tokenURI） | 是（NFT 本身有价值） | 高（铸造权限、元数据） | 成就系统、会员凭证 |

| **积分记录**​ | 为用户增/减积分，查询余额 | 3~5 | 是（地址→积分映射） | 是（积分可兑换） | 中（加减权限控制） | 游戏内货币、忠诚度计划 |

| **Onchain Todo**​ | 创建待办事项，标记完成/删除 | 5~10 | 是（待办列表、ID 映射） | 否 | 低（仅本人可操作） | 个人任务管理（链上版） |

\- 链上产品和普通互联网产品有什么不同：普通互联网产品通常由公司服务器保存用户账号、数据和业务状态，用户用账号密码登录，操作结果主要记录在平台数据库里。链上产品则把关键状态和交易记录写到区块链上，用户通过钱包签名确认操作，地址和交易可以在区块浏览器公开查询。因此链上产品更透明、可验证，也更强调用户自己保管资产和私钥安全。

1\. Testnet 是什么？

\---------------

**Testnet = 测试网。**

第一性原理地说，区块链网络本质上是一群节点按照同一套规则维护同一本账本。\*\*Mainnet 主网\*\*是真钱、真实资产、真实交易；\*\*Testnet 测试网\*\*是给开发者和学习者练习用的“仿真环境”。Ethereum 官方把 testnet 类比为软件开发里的 **staging server / 预发布环境**：在部署到主网前，先在测试网测试合约和应用。测试网资产一般没有真实价值，通常通过 faucet 免费领取。(\[[ethereum.org](http://ethereum.org)\]([https://ethereum.org/developers/docs/networks/](https://ethereum.org/developers/docs/networks/) "Networks | [ethereum.org](http://ethereum.org)"))

你拿到的 **55 MON** 是 Monad Testnet 上的测试 MON，作用是：

支付测试网 gas

测试转账

测试合约交互

测试 DApp

它不是主网 MON，也不是可当真钱使用的资产。

2\. 当你在 MetaMask 里选择不同 Networks 时，发生了什么？

\---------------------------------------

你不是在“换钱包”，而是在让同一个钱包连接到\*\*不同的区块链账本\*\*。

可以这样理解：

你的钱包地址：

0xABC...

在 Ethereum Mainnet 上：

可能有 0.1 ETH

在 Monad Testnet 上：

可能有 55 MON

在 Sepolia 上：

可能有 0.5 Sepolia ETH

在 Polygon 上：

可能有 10 MATIC

地址看起来可以是同一个，但它连接的是不同网络，所以余额、交易历史、Gas 代币、区块浏览器都不同。Ethereum 官方文档也说明，同一个 Ethereum 账户可以在不同网络上使用，但主网上的余额和交易历史不会自动带到其他网络。(\[[ethereum.org](http://ethereum.org)\]([https://ethereum.org/developers/docs/networks/](https://ethereum.org/developers/docs/networks/) "Networks | [ethereum.org](http://ethereum.org)"))

所以你切换 Network，本质上是在切换：

RPC：钱包向哪个网络节点询问数据

Chain ID：当前是哪条链

Gas Token：用什么币付手续费

Explorer：去哪里查交易

State：读取哪一本账本

Monad Testnet 的 Chain ID 是 **10143**，Token 是 **MON**，官方开发者入口也列出了 RPC、Explorer 和 Faucet 等信息。(\[Monad Developer Portal\]([https://developers.monad.xyz/](https://developers.monad.xyz/) "Monad Developer Portal"))

为什么有这么多网络？因为不同链在做不同事情：

Ethereum Mainnet：真实生产环境

Sepolia / Hoodi：Ethereum 测试环境

Monad Testnet：Monad 的测试环境

Polygon / Arbitrum / Base：不同扩容链或生态链

本地网络：开发者自己电脑上跑的临时链

Ethereum 官方也说，除了唯一的 Ethereum Mainnet，任何人都可以创建遵循相同协议规则但彼此不交互的独立网络，用于测试和开发。(\[[ethereum.org](http://ethereum.org)\]([https://ethereum.org/developers/docs/networks/](https://ethereum.org/developers/docs/networks/) "Networks | [ethereum.org](http://ethereum.org)"))

\* \* \*

3\. 区块浏览器是什么？

\------------

**区块浏览器 = 区块链的公开查询网站。**

普通互联网里，你的订单、支付记录、后台日志在公司数据库里，外人看不到。链上世界里，交易、地址、区块、合约调用是公开账本的一部分，所以需要一个“搜索引擎”把这些数据展示出来。

区块浏览器可以查：

地址 Address

余额 Balance

交易 Transaction

交易哈希 Transaction Hash

区块 Block

合约 Contract

Gas Fee

交易成功或失败

Etherscan 自称是 Ethereum 的区块浏览器和分析平台，可以探索交易、地址、代币、价格和其他链上活动；Monad 也有自己的测试网浏览器，比如 Monadscan / MonadVision。(\[Ethereum (ETH) Blockchain Explorer\]([https://etherscan.io/index?utm\_source=chatgpt.com](https://etherscan.io/index?utm_source=chatgpt.com) "Ethereum (ETH) Blockchain Explorer - Etherscan"))

一句话：

\> **钱包负责发起操作，区块浏览器负责验证这件事是否真的发生在链上。**
